# Palette clipboard improvement goal

Continuously improve the existing Palette desktop launcher at `tools/palette`, focusing on clipboard management on macOS. Build on the current implementation, preserve working launcher behavior, and iterate until the clipboard experience is visually polished, reliable, and fast enough for everyday use. A user should be able to find a previous clip by the app it came from and paste it into their current work within five seconds in representative retrieval tasks.

Use [the approved clipboard concept](clipboard-target.png) as the visual target. Recreate its compact dark floating panel, restrained lavender selection, source-app sidebar, searchable history, content-type filters, rich preview, clear metadata, and visible keyboard actions. Match the hierarchy, density, spacing, typography, and focus treatment in the running app. Adapt the layout to real window sizes and long content without clipping or sacrificing readability. Replace Palette’s app, menu-bar, and interface icon with the two overlapping outlined squares shown in the concept, keeping it recognizable at small sizes.

Organize history automatically by source application. Provide All apps and Pinned views, app names and icons, and filters that combine app, content type, and search. Keep source attribution useful after restart and when an app is unavailable. Support unknown sources honestly. Preserve app-specific history and existing pins when deduplicating repeated copies; Palette’s own clipboard restores must not create misleading copies or change their provenance.

Capture and restore text, links, images, and files in their appropriate native clipboard formats. Show readable text and link previews, useful image thumbnails and dimensions, and recognizable file information. Restore files as files and images as images. Preserve relevant rich-text representations. Keep clipboard payloads and previews local and encrypted at rest, and bound storage and background work so image-heavy use does not make the launcher sluggish.

Make the complete retrieval and management flow work from the keyboard. Support opening clipboard history, searching, switching filters, navigating results, previewing, copying, pasting to the previously active app, pinning, unpinning, deleting, and dismissing. Preserve focus predictably. Make permission-dependent paste behavior explicit and provide a working copy alternative. Handle empty history, no matches, paused capture, missing files, unavailable target apps, and storage or permission failures without claiming success.

Expose straightforward capture, retention, capacity, and excluded-app controls. Preserve encrypted local storage and sensitive-content exclusions. Ensure policy changes take effect predictably and survive restart. Verify that capture pause, app exclusions, sensitive clipboard markers, and self-capture prevention work through actual use. Do not expose personal clipboard contents in committed screenshots, logs, or review evidence; use an isolated review profile and synthetic content.

Work in repeated improvement cycles. Capture the current baseline, identify the highest-impact gaps, implement a focused change, exercise the affected flows in the running app, and compare fresh captures against both the baseline and the approved concept. Keep improvements, resolve regressions, and repeat. Evaluate text, link, image, and file states; short and long histories; app-filtered and pinned views; and keyboard-only use rather than optimizing one staged screenshot.

Use demanding independent reviewer agents during iterations. Assign separate ownership for (1) visual fidelity, layout, icon consistency, and content readability; (2) keyboard interaction, focus, accessibility, and everyday retrieval speed; and (3) native clipboard fidelity, source attribution, deduplication, persistence, privacy, and performance. Reviewers should inspect the current implementation and fresh runtime evidence, identify concrete reproducible problems, and distinguish verified behavior from assumptions. Give reviewers bounded independent work; coordinate access so only one agent controls a live app instance at a time. Fix substantive findings and obtain follow-up reviews of the affected areas. Require independent review of the final build, not merely a favorable earlier pass.

Do not create or run automated tests. Validate with builds, type checks, source review, and deliberate hands-on runtime checks. On the final build, verify captures from multiple apps, combined search and filters, all supported native clipboard formats, pin/unpin/delete, repeated copying without losing pins or provenance, pause and exclusions, restart persistence, return-to-app paste, copy fallback, and keyboard-only retrieval. Check representative larger histories and image-heavy use for noticeable stalls and memory growth under stated conditions. Record failures as well as fixes and repeat relevant runtime checks after changes.

Keep the implementation simple and explicitly owned: native OS integration in the platform host, product behavior in shared services, and clipboard presentation in a focused UI surface. Make the smallest complete changes, remove replaced code, and avoid unrelated refactors. Preserve existing platform contracts or handle unsupported capabilities explicitly rather than implying unverified feature parity.

Commit completed improvements with updated launch instructions, comparable before-and-after captures, independent review findings, final verification evidence, and an honest account of remaining gaps. Push completed work to `main` following repository instructions. Do not stop after cosmetic changes, a favorable screenshot, or one review pass while substantial actionable gaps remain.
