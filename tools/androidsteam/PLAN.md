# Android Steam delivery plan

## Objective

Deliver the polished native Android Steam launcher in [README.md](README.md) and [the concept](docs/android-steam-concept.png), preserving the existing Linux runtime, authenticated Steam account and owned games on the Android 16 Samsung S24. Follow [AGENTS.md](AGENTS.md). Steam owns authentication, installs/updates and game execution; native Kotlin Views/XML owns the mobile library, vertical search, details, profile and Setup navigation.

## Milestones

- [x] **1. Proven launch baseline:** finish Superflight direct launch through Steam by app ID with an explicit compatible ARM64 Proton tool and arguments. Prove those settings reach the game; validate gameplay, clean exit/relaunch, diagnostic logs and initial release measurements before changing runtime.
- [x] **2. Runtime migration:** investigate pinned Ubuntu Base ARM64 and Arch Linux ARM AArch64 against actual Steam/Proton/graphics/Android requirements, full installed size, reproducibility, maintenance and measured behavior. Implement the chosen replacement for Ubuntu Minimal; preserve home separately, pin packages/drivers and validate the same baseline, fresh install, migration, restart and recovery. Ship one runtime after checks pass.
- [ ] **3. Gameplay foundation:** persist per-game Proton/arguments/environment/control profiles and prove application after app/Steam restart. Distinguish native Linux from Proton execution. Validate Superflight, Brotato and one available more demanding owned title with meaningful gameplay, audio, touch/controller input, exit/relaunch, Home/resume and failure recovery; record exact working configurations and limitations.
- [ ] **4. Native redesign:** match the README concept with real ownership/install metadata, official artwork, compact library rows, linear search, details, profile/setup and Library/Search/Downloads navigation. Provide pre-launch compatibility/controls, reuse one session on Play and return to the native launcher after exit. Preserve Steam prompts/management; no fabricated state or hardcoded examples.
- [ ] **5. Measurement and polish:** compare release builds on the same S24/workloads for native startup, cold/warm game launch, memory, idle CPU, frame pacing and sustained gameplay where measurable. Fix demonstrated bottlenecks; refine visuals, scrolling, keyboard, orientation, loading/errors and cleanup. Focused checks, brief documentation/licenses, release artifact and commits/pushes to main without force.

## Completion criteria

- Implemented and validated Ubuntu Base or Arch Linux ARM migration, preserving login, installed games, saves and working configuration.
- Reliable direct launch with persistent explicit Proton/arguments and representative gameplay with audio and usable controls; a menu alone is insufficient.
- Native design matches the concept with Profile → Setup, accurate ownership/install/supported state and reliable game/session lifecycle.
- Recorded measurements, passing focused checks and finished changes on main. Report working configurations, unsupported cases, external blockers and commits.
- The finished app works independently of the development Mac. Its Steam cache can inform file formats/artwork, but ownership/install/session state comes from the S24; never copy authentication or hardcode the Mac library.
- Resume the next unfinished milestone after compaction; preserve completed work. Emulator support remains future scope.
