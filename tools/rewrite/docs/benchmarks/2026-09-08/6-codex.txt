Hi everyone,

I wanted to send a proper update about the customer onboarding project before we meet on Thursday. There have been several conversations in different places, and I don’t think everyone has the same understanding of where things stand. This message is for our internal team only. Please don’t forward it to customers yet, since a couple of the dates are still proposals and we need to agree on responsibilities before announcing anything.

The main thing we learned from the pilot is that people can usually create their accounts without help, but they get confused immediately afterward. They land on an empty dashboard and aren’t sure whether to invite a colleague, import existing information, or create a new project. We originally assumed the welcome email would explain this; however, several participants never opened the email because they were already in the product. Two people also said they thought the empty dashboard meant their accounts hadn’t been fully activated. I think we should address this in the product itself rather than add another reminder email.

For the next version, I suggest showing three short steps directly on the dashboard. The first should help customers create a real project, the second should let them add a small amount of information, and the third should explain how to invite someone else. The steps should be optional, and people should be able to close them without losing their progress. We also need to avoid making it seem as though inviting a colleague is required to use the product. Several of our smaller customers work alone, and they shouldn’t feel that they’re doing something wrong.

There is a separate issue with the import flow that I don’t want us to lose track of. The current error message simply says that the file couldn’t be processed, even when we know exactly which column is missing. Could we show the missing column name and link to the sample file? I’m not asking for a completely new import system this month. A clearer explanation and an example would already make a big difference. The sample file is available at https://example.com/onboarding/sample.csv, and the reference document is https://example.com/docs/import. Please keep both links in the final notes so the support team can find them easily.

On timing, my proposal is to have the dashboard changes ready for internal review on September 18, then invite five existing customers to try them on September 23. This is not a confirmed launch date. If the import issue takes longer than expected, we can test the dashboard separately rather than hold everything back. We should decide on the wider rollout after reviewing the feedback, not before. I would prefer to leave at least two working days between the customer sessions and the rollout decision so we don’t make changes based only on the first conversation.

For responsibilities, I’ve written down a first pass below. These are suggestions based on what we discussed yesterday, so please correct anything that doesn’t match your availability. We also need to be careful about how we measure whether the changes actually help. Counting how many people click the checklist isn’t enough. I suggest looking at whether a new customer creates a project and adds useful information during their first session, as well as whether they need to contact support to get that far. It would be helpful to compare those numbers with the previous onboarding flow, but only if we use the same definitions. Please don’t combine trial accounts created by our own team with real customer accounts, since that made the numbers look much better last time than the actual experience was.

There are two things deliberately outside this proposal. We are not changing pricing, and we are not moving existing customer data automatically. A few people mentioned both topics during the pilot, but they are separate decisions with different risks and additional stakeholders. If a customer asks about either topic during a feedback session, please record the question and tell them we’re collecting feedback. Don’t promise a date or suggest that a change has already been approved.
