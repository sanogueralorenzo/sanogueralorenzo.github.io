I wanted to send a clear update about the customer onboarding project before we meet on Thursday. We’ve had several conversations in different places, and I’m not sure everyone has the same understanding of where things stand.

This message is for our internal team only. Please don’t forward it to customers yet: some dates are still proposals, and we need to confirm ownership before announcing anything.

The main lesson from the pilot is that people can usually create an account without help, but they become confused immediately afterward. They land on an empty dashboard and aren’t sure whether to invite a colleague, import existing information, or create a new project. We originally assumed the welcome email would explain this, but several participants never opened it because they were already using the product. Two people also thought the empty dashboard meant their accounts weren’t fully activated. I think we should address this in the product itself rather than add another reminder email.

For the next version, I suggest showing three short steps directly on the dashboard:

1. Create a real project.
2. Add a small amount of information.
3. Learn how to invite someone else.

The steps should be optional, and users should be able to close them without losing their progress. We should also avoid implying that inviting a colleague is required, since several smaller customers work alone and shouldn’t feel they’re doing something wrong.

There is a separate issue with the import flow that we shouldn’t lose track of. The current error message only says that the file couldn’t be processed, even when we know which column is missing. Could we show the missing column name and link to the sample file? I’m not suggesting a completely new import system this month; a clearer explanation and an example would already make a significant difference.

The sample file is available at https://example.com/onboarding/sample.csv, and the reference document is https://example.com/docs/import. Please keep both links in the final notes so the support team can find them easily.

On timing, I propose having the dashboard changes ready for internal review on September 18, then inviting five existing customers to try them on September 23. These are not confirmed launch dates. If the import issue takes longer than expected, we can test the dashboard separately rather than hold everything back. We should decide on the wider rollout after reviewing the feedback, not before. I’d prefer to leave at least two working days between the customer sessions and the rollout decision so we don’t make changes based only on the first conversation.

We also need to be careful about how we measure whether the changes actually help. Counting checklist clicks isn’t enough. I suggest tracking whether a new customer creates a project and adds useful information during their first session, as well as whether they need to contact support to do so. It would be helpful to compare these figures with the previous onboarding flow, but only if we use the same definitions. Please don’t combine trial accounts created by our own team with real customer accounts; doing so made the numbers look much better last time than the actual experience was.

Two things are deliberately outside this proposal: changing pricing and automatically moving existing customer data. A few people mentioned both topics during the pilot, but they are separate decisions with different risks and stakeholders. If a customer asks about either topic during a feedback session, please record the question and say that we’re collecting feedback.
