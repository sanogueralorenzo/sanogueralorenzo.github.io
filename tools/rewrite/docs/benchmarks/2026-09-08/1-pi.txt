I wanted to send a proper update about the customer onboarding project before we meet on Thursday. There have been several conversations in different places, and I’m not sure everyone has the same picture of where things stand. This message is for our internal team only. Please don’t forward it to customers yet, since some dates are still proposals and we need to agree on responsibilities before announcing anything.

The main lesson from the pilot is that people can usually create their account without help, but they become confused immediately afterward. They land on an empty dashboard and aren’t sure whether to invite a colleague, import existing information, or create a new project. We originally assumed the welcome email would explain this; however, several participants never opened it because they were already in the product. Two people also said they thought the empty dashboard meant their account hadn’t been fully activated. I think we should address this in the product itself rather than add another reminder email.

For the next version, I suggest showing three short steps directly on the dashboard. The first should help customers create a real project, the second should let them add a small amount of information, and the third should explain how to invite someone else. The steps should be optional, and people should be able to close them without losing their progress. We also need to avoid making it seem as though inviting a colleague is required to use the product. Several of our smaller customers work alone, and they shouldn’t feel they are doing something wrong.

There is a separate issue with the import flow that I don’t want us to lose track of. The current error message only says that the file couldn’t be processed, even when we know which column is missing. Could we show the missing column name and link to the sample file? I’m not asking for a completely new import system this month. A clearer explanation and an example would already make a big difference. The sample file is available at https://example.com/onboarding/sample.csv, and the reference document is https://example.com/docs/import. Please keep both links in the final notes so the support team can find them easily.

On timing, my proposal is to have the dashboard changes ready for internal review on September 18, then invite five existing customers to try them on September 23. These are not confirmed launch dates. If the import issue takes longer than expected, we can test the dashboard separately rather than hold everything back. We should decide on the wider rollout after reviewing the feedback, not before. I’d prefer to leave at least two working days between the customer sessions and the rollout decision so we don’t make changes based only on the first conversation.

We also need to be careful about how we measure whether the changes actually help. Counting checklist clicks isn’t enough. I suggest looking at whether a new customer creates a project and adds useful information during their first session, and whether they need to contact support to get that far. It would be helpful to compare those numbers with the previous onboarding flow, but only if we use the same definitions. Please don’t combine trial accounts created by our own team with real customer accounts. Doing so made the numbers look much better last time than the actual experience was.

Two things are deliberately outside this proposal: we are not changing pricing, and we are not automatically moving existing customer data. A few people mentioned both topics during the pilot, but they are separate decisions with different risks and additional stakeholders. If a customer asks about either topic during a feedback session, please record the question and tell them we are collecting feedback. Don’t promise a date or suggest that a change has already been approved. The budget for this onboarding iteration is $4,500; anything beyond that requires a separate discussion before we spend it.
