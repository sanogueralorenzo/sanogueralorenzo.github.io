Hi everyone, I wanted to send a proper update about the customer onboarding project before we meet on Thursday, because there has been quite a few conversations in different places and I don't think everybody have the same picture of where things stand. This message is a draft for our internal team only. Please don't forward it to customers yet, since a couple of the dates are still proposals and we need to agree who is responsible for each part before we announce anything.

The main thing we learned from the pilot is that people can usually create their account without help, but they gets confused immediately afterwards. They land on an empty dashboard and aren't sure if they should invite a colleague, import their existing information, or create a new project. We originally assumed that the welcome email would explain this, however several participants never opened the email because they were already in the product. Two people also said that they thought the empty dashboard meant that their account wasn't fully activated. I think this is something we should fix in the product itself instead of adding another reminder email.

For the next version, I suggest we show three short steps directly on the dashboard. The first should help the customer create one real project, the second should let them add a small amount of information, and the third should explain how to invite someone else. The steps should be optional and people should be able to close them, but closing the panel shouldn't delete their progress. We also need to avoid making it look like inviting a colleague is required to use the product, because several of our smaller customers work alone and they shouldn't feel like they are doing something wrong.

There is a separate issue with the import flow that I don't want us to lose track of. The current error message just says that the file couldn't be processed, even when we know exactly which column is missing. Could we show the missing column name and link to the sample file? I'm not asking for a completely new import system this month. A clearer explanation and an example would already make a big difference. The sample file is available at https://example.com/onboarding/sample.csv, and the reference document is https://example.com/docs/import. Please keep both links in the final notes so the support team can find them easily.

On timing, my proposal is to have the dashboard changes ready for internal review on September 18, then invite five existing customers to try them on September 23. This is not a confirmed launch date. If the import issue takes longer than expected, we can test the dashboard separately rather than holding everything back. We should make a decision about the wider rollout after we have reviewed the feedback, not before. I would prefer that we leave at least two working days between the customer sessions and the rollout decision so we don't end up making changes based only on the first conversation.

For responsibilities, I have written down a first pass below. These are suggestions based on what we discussed yesterday, so please correct anything that doesn't match your availability. Maya would own the dashboard copy and the first version of the three steps. Jordan would look at the import error and confirm whether we can identify missing columns reliably. Alex would coordinate the five customer sessions and make sure we include at least one person who works alone. I can pull the feedback together, but I will need someone to review my summary because I won't be able to attend every session. Nobody should assume that these assignments are final until we confirm them on Thursday.

We also need to be careful about how we measure whether the changes actually helps. Counting how many people click the checklist isn't enough. I suggest we look at whether a new customer creates a project and adds useful information within their first session, and whether they need to contact support to get that far. It would be helpful to compare those numbers with the previous onboarding flow, but only if we are using the same definitions. Please don't combine trial accounts created by our own team with real customer accounts, as that made the numbers look much better last time than the actual experience was.

There are two things that are deliberately outside this proposal. We are not changing pricing, and we are not moving existing customer data automatically. A few people mentioned both topics during the pilot, but they are separate decisions with different risks and more people involved. If a customer asks about either topic during a feedback session, please record the question and tell them we are collecting feedback. Don't promise a date or suggest that a change has already been approved. The budget available for this onboarding iteration is $4,500, and anything beyond that needs a separate discussion before we spend it.

Before Thursday, could each owner add a short note with their main dependency, their biggest concern, and whether the proposed dates seem realistic? A few sentences is enough, we don't need a slide deck. If you disagree with the approach, please explain the specific customer problem you think it would miss so we can discuss that directly. I'd also appreciate any feedback on the wording of the three steps, especially from people who have recently helped a customer get started.
