# Amarchy

## Objective

Create a polished Android host for the most complete practical upstream ARM64 Omarchy desktop. Build and bundle a preconfigured environment using upstream Omarchy packages, applications, shell, menus, themes and defaults wherever compatible. Limit custom code to Android graphics, touch, keyboard, audio, clipboard and session lifecycle. Adapt or omit system features that cannot work in an unrooted Android app, using small explicit adaptations and removing replacements when upstream works. Preserve one-tap setup and persistent user files. Assess current implementation and upstream ARM64 support, verify the actual desktop/core applications in the emulator, follow repository AGENTS guidance, and commit/push to main.

## Completion criteria

- One primary action prepares a verified environment and enters the real desktop; later opens reuse setup/session state.
- A polished, accessible frontend handles progress, cancellation, retry, storage/network failures, keyboard access, and session controls.
- The real upstream Omarchy shell, bar, menus, launcher, theme switching, terminal/shell defaults, editor configuration and compatible core applications render and operate. The package profile starts from upstream ARM64 defaults, with a reviewed disposition for every package and incompatible system feature.
- Android integration provides readable resizing, touch/keyboard, audio and clipboard. Background/resume, stop/relaunch, process cleanup, and persistent home data work.
- Runtime inputs and upstream adaptations are pinned, reproducible, and attributed.
- Focused checks and documented emulator/device evidence pass; completed changes are committed and pushed to main.

## Milestones

1. Establish the Android project, installation/session ownership, and polished one-action frontend.
2. Prove ARM64 Linux execution and display transport on Android 16 in the emulator.
3. Replace the selected desktop subset with an upstream-derived ARM64 runtime: full shell/assets/configuration, compatible default packages and explicit Android adaptations.
4. Prove upstream menus/launcher/themes/core apps and remove custom desktop replacements as their upstream equivalents work.
5. Finish Android audio/clipboard/input, lifecycle/recovery/accessibility, reproducibility, brief documentation and release acceptance.

## Upstream assessment (2026-10-12)

- Existing implementation is a selected subset: 482-package Arch Linux ARM closure, source revision `9480d1b6a98156314dbabe6bfef08f39f8b9cd07`, custom Android Apps menu, custom Bash/Foot config and Everforest overrides. `runtime/build.py` omits the entire upstream `shell/`, installation/provisioning scripts and graphical assets. Pacman's installed-package database is absent. These gaps prevent working upstream shell/menu/theme/app detection even though Hyprland renders.
- The pinned upstream source already has `omarchy-pkg-defaults aarch64`, base/aarch64 lists and an explicit x86-only list. Its current shell/menu use Quickshell and plugin IPC. Complete user defaults and theme provisioning are upstream code; use them instead of recreating their behavior.
- Live official `https://pkgs.omarchy.org/stable/aarch64/omarchy.db` serves 59 packages and `edge/aarch64/omarchy.db` serves 180. Edge includes Omarchy/settings, Quickshell, Omarchy Neovim, first-party apps and missing desktop dependencies. Pin reviewed exact inputs; never silently refresh during a build. The ARM ecosystem now supports substantially more than the existing Amarchy seed list.
- Official `omacom/try-omarchy` builds a pinned ARM64 environment from Arch Linux ARM packages plus upstream source, with explicit host adaptations. Its Mac VM has systemd/kernel capabilities unavailable to this Android PRoot session; reuse its upstream approach and evidence, not VM boot/device machinery. Current upstream HEAD is `defbf90e893e741067e48f4a27d2ec694c71358e`; retain/review source pins deliberately against matching package versions.
- Android exclusions must describe actual limitations: kernel/boot/disk encryption, display manager/login, direct Wi-Fi/Bluetooth/backlight/USB device control, privileged firewall/container operations, and systemd-dependent system services. Preserve compatible user-space functionality. Enumerate package/service adaptations before expanding the bundle; do not label untested components impossible merely because they need work.

Home retains the session; Close desktop stops it. The session runs as guest UID 1000 through the official session starter. Projects/settings live in a separate persistent home.
- The checksum-verified runtime contains 482 pinned ARM64 packages and Omarchy revision `9480d1b6a98156314dbabe6bfef08f39f8b9cd07`. Its bootstrap, helpers, look/feel and tiling defaults load with Android overrides. Terminal, Nautilus, Neovim and Chromium render. Touch/mouse/physical keys, Android IME Unicode typing, clipboard paste and shortcut controls work. Full-OS boot/hardware services are excluded.
- Deterministic gzip replaces Java XZ extraction. The asset is named `environment.tar.gzip` to prevent Android's asset merger from transparently expanding `.gz`. Archive: 946877315 bytes, SHA256 `a8b315f98bc57581eafc137c4f8fa9cf8e3bcfb4999f27f9fb42319d81e082ef`; regular files: 2609773598 bytes.
